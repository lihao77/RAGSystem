# RAGSystem

English | [中文](README.md)

RAGSystem is a local-only, agent-first full-stack project for multi-agent collaboration across independent work scenes. Its main runtime is a Fastify/TypeScript backend with a Vue 3 frontend, focused on ReAct-style orchestration, multi-agent execution, Skills, WebSocket interaction, Memory, Hooks, and MCP integration.

## Key Features

- Multi-agent orchestration driven by an Orchestrator Agent for delegation, collaboration, and continuous execution
- Child agent sessions with unified `agent` create, resume, and bidirectional messaging flows
- Realtime interaction where `POST /api/agent/stream` starts a run and the session WebSocket delivers message chunks, execution steps, approvals, user input requests, and reconnect replay events
- Extensible runtime with local tools, Skills, and MCP server integration
- Memory recall, session memory write-back, and Hook-based event extensibility
- Runtime-managed configuration for Agent teams, model providers, MCP servers, and vectorizers
- Web UI for chat, execution process inspection, the run workbench, agent studio (team and agent configuration), MCP management, knowledge bases, model providers, the skill library, and system configuration

The admin center exposes an Agent Studio entry (`/agent-studio`) for composing teams and refining individual agents before they run.

## Tech Stack

- Backend: Fastify, TypeScript, WebSocket, SQLite, MCP
- Frontend: Vue 3, Vite, Axios, ECharts, MapLibre GL
- Runtime: Agent-first orchestration with ReAct-style execution, Skills, Memory, Hooks, and runtime-managed local config

## Quick Start

### 1. Prerequisites

- Node.js 22.5+
- npm
- Chrome or Edge, only for screenshot generation

### 2. Environment and Runtime Config

Copy the environment templates first:

```bash
# Workspace-level npm commands read .env from the invoking directory, so copy it to the repository root
cp backend-local/.env.example .env
cp frontend-client/.env.example frontend-client/.env
```

The TypeScript backend reads effective configuration from the runtime data directory. Model providers, Agent teams, MCP servers, and vectorizers can be managed from the frontend administration pages.

Backend plugins are declared exclusively by `backend-local/backend.plugins.yaml`, including module paths, activation, ordering, and initialization options. Installing a third-party plugin normally requires only installing its npm package and editing the matching YAML file. See [Backend Plugin Configuration](docs/BACKEND_PLUGIN_CONFIG.md) for the schema and module contract.

- Default runtime data root: `~/.ragsystem`
- If `RAG_DATA_ROOT` is set, the runtime data root becomes `<RAG_DATA_ROOT>`
- Each scene's runtime config files live under `<data-root>/tenants/<scene-id>/config`; the default scene ID is `tnt_local`:
  - `app/config.yaml`
  - `agents/team_index.yaml`
  - `agents/teams/*.yaml`
  - `model_adapter/providers.yaml`
  - `vector_store/vectorizers.yaml`
  - `mcp/mcp_servers.yaml`

For fuller run, configuration, and verification guidance, see [docs/OPERATIONS.md](docs/OPERATIONS.md).

### 3. Start the Backend

```bash
npm run dev:backend-local
```

The backend listens on `http://localhost:5002` by default. Use `BACKEND_TS_HOST`, `BACKEND_TS_PORT`, or `PORT` to adjust startup behavior. If `frontend-client/dist` exists, the backend also serves the built frontend assets.

### 4. Start the Frontend

```bash
cd frontend-client
npm install
npm run dev
```

The frontend runs on `http://localhost:5174` by default and proxies `/api` plus WebSocket traffic to `http://localhost:5002`. Configure `VITE_DEV_PORT` and `VITE_API_PROXY_TARGET` in `frontend-client/.env` when needed.

### 5. Start with Docker

Use the default compose file for Local mode:

```bash
docker compose up --build
```

Open `http://localhost:8080` to start using the app. No installation wizard or login is required. The Local Scenes plugin manages independent work contexts.

### 6. Build a Windows Installer

The Electron installer uses the same TypeScript backend as browser development. Its build creates a standalone backend bundle and verifies Electron's `node:sqlite` plus `sqlite-vec` support before packaging.

Install the desktop wrapper dependencies first:

```bash
cd desktop-electron
npm install
```

Then build the installer:

```bash
cd ../desktop-electron
npm run build:installer
```

The build pipeline will:

- Build `frontend-client/dist`
- Build and probe the standalone `backend-local` desktop bundle
- Use `electron-builder` to output the NSIS installer to `desktop-electron/release/`

The installed desktop app will:

- Start the local TypeScript backend using Electron's Node mode
- Open the built-in window at `http://127.0.0.1:5002`
- Store runtime data under `~/.ragsystem/`
- Pin the backend process working directory to `~/.ragsystem`, avoiding runtime writes to read-only install directories such as `Program Files`
